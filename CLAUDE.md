# OpenXcom screen reader fork

A personal accessibility fork of OpenXcom for playing with a screen reader through Tolk on Windows. There's one target user, so favour minimum viable over generality. Upstream submission isn't planned.

## This branch: OXCE

- `oxce-accessibility` is the accessibility layer on **OpenXcom Extended** (OXCE, `MeridianOXC/OpenXcom`, branch `oxce-plus`), started 2026-10-05 by merging the vanilla `accessibility` branch into `oxce/oxce-plus`. The vanilla branch stays as the fallback; OXCE is where work goes from now on, unless the user says otherwise.
- Checked out as a git worktree at `C:\git\OpenXcom-oxce` (same repository as `C:\git\OpenXcom`, which holds `accessibility`). Remotes: `origin` (the user's fork), `upstream` (vanilla), `oxce` (OXCE). OXCE merges vanilla upstream itself, so take updates from `oxce/oxce-plus`.
- OXCE's own user folder: `run.cmd` passes `-user`/`-config` `Documents\OpenXcom Extended`, so its saves, options, `openxcom.log` and `speech.log` live there, apart from vanilla's. OXCE saves don't load in vanilla.
- OXCE differences the port had to absorb (2026-10-05): weapons have several ammo slots (`getAmmoForSlot`, `getCompatibleAmmoForSlot`, `getSlotForAmmo`; the layer reads slot 0); `Tile::isDiscovered` takes a `TilePart` (the whole tile is `O_FLOOR`; `Battle.cpp`'s `discovered()` maps vanilla's 0/1/2); craft have up to `RuleCraft::WeaponMax` weapons (dogfight loops `getWeaponCount()`); facilities are `getSizeX`/`getSizeY` and placement reasons come from `getPlacementError` (the layer asks `BaseView::getPlacementErrorAt`); several craft can be sent together (`SelectDestinationState::getCrafts`, `MultipleTargetsState(targets, crafts, state, customSound)`); the debriefing has three pages (`getPageNumber`: scores, soldier stats, loot with Sell/Transfer); damage is applied when an `ExplosionBState` starts, so the impact snapshot brackets the `hit`/`explode` calls in `init()`; path steps return `PathfindingStep`.
- OXCE has a few dozen screens vanilla lacks (Stats for Nerds, tech tree viewer, global research/manufacture, UFO tracker, notes, pilots, training...) and extra buttons on familiar screens. Only a handful have recipes (end-mission confirmation, new possible purchase/craft/facility); `docs/oxce-audit.md` ("Uncovered screens") is the current list. There's no generic fallback (read 2026-10-05, not yet confirmed in play): when no recipe matches, `Navigator::sync` speaks nothing on arrival and claims no keys but Ctrl+R. The typing echo and game-side hooks (warnings, dogfight status) still speak, and `Battle`/`Geo` narration pauses until the state closes. OXCE also has its own hotkeys (Ctrl+N notes and more); the layer's keys take priority, so an OXCE key we also claim is swallowed.
- **Don't assume vanilla behaviour.** `docs/oxce-audit.md` (2026-10-05) lists every known place where the layer's assumptions and OXCE disagree, with OXCE file:line citations; work through it, and read the OXCE handler before driving it. Two general rules came out of it: OXCE hides buttons to forbid their action, so `Controls::click` refuses hidden surfaces ("unavailable"); and OXCE handlers read the live modifier state, so `Navigator::handleEvent` clears it while the layer acts (`ModifierMask`). To use an OXCE Shift/Ctrl variant on purpose, a recipe reads `Navigator::keyModifiers()` and wraps the drive in `Controls::withModifiers` (Intercept's Shift+Enter wing does), and says what happened.

## Building

Visual Studio 2022 is installed; build `src/OpenXcom.2010.sln` with MSBuild (the solution is the primary build, CMake is kept in sync but secondary):

```
"C:/Program Files/Microsoft Visual Studio/2022/Community/MSBuild/Current/Bin/MSBuild.exe" src/OpenXcom.2010.sln -p:Configuration=Release -p:Platform=x64 -m -v:minimal -nologo
```

- A full rebuild takes several minutes; run it in the background.
- Output: `bin/x64/Release/OpenXcom.exe`. The post-build step copies every DLL in `deps/lib/<platform>/` to `bin/<platform>/` (one level above the exe).
- C++17 (OXCE builds as C++17 already). OXCE uses rapidyaml instead of yaml-cpp and ships its own SDL DLLs in `deps/lib`.
- The log is full of warnings from upstream code; only look at warnings in files you touched.

### Adding a source file

Add it in **three** places: `src/OpenXcom.2010.vcxproj` (ClCompile/ClInclude), `src/OpenXcom.2010.vcxproj.filters` (with a `<Filter>`), and `src/CMakeLists.txt` (the matching `*_src` list; `.cpp` files only, headers go just in the first two).

### File format gotchas

- Source files are checked out with **CRLF**; the `.vcxproj` and `.filters` files are also UTF-8 **with BOM**. Preserve both.
- **Don't use `sed -i` from Git Bash on these files**: it silently strips the CRs and the pattern then fails to match. Use the Edit tool, or a Python script that reads/writes bytes.
- Backslashes in heredoc'd Python get mangled through the Bash tool; write such scripts to a file first.

## Tolk

- Loaded at runtime (`LoadLibraryExW` + `GetProcAddress`), so there's no header or import lib; a missing DLL means silence, not a crash. It tries the exe folder, then its parent, then the normal search order.
- DLLs in `deps/lib/x64/` (Tolk, nvdaControllerClient64, SAAPI64) and `deps/lib/Win32/`. They're **not tracked by git** (`*.dll` is ignored; OXCE's SDL DLLs beside them were force-added and are tracked). Sources: `C:\git\glfrontier-extended\tolk\x64\` and `C:\git\dangerous-access\libs\tolk\` (32-bit).
- SAPI is enabled as a fallback, so if NVDA isn't running at launch, speech goes to SAPI.

## Accessibility architecture

The design follows the Graph A11y Kernel spec at `C:\git\sims2access\docs\graph-a11y-spec.md`. Read it before building navigation or screens.

- **Menus and popups** become graph screens: an immediate-mode parallel UI tree rebuilt from live game state on each operation. The plan is to reuse the C++ kernel from `C:\git\sims2access\src\Graph\` (with tests in `tests\graph\`).
- **The battle map is not a graph.** It's a separate exploration layer (keyboard tile cursor) that's active only when no graph screen claims the keyboard.
- Axioms to follow everywhere:
  - **Announce once:** a differ over the focused identity (for example the selected unit or cursor tile), not hand-placed announce calls.
  - **Parity:** never reveal what a sighted player can't see. Gate on `Tile::isDiscovered` and visible-unit lists.
  - **Interrupt by provenance:** responses to the player's keypresses interrupt; event narration queues.
  - **One vocabulary module:** every string the mod authors goes through `Access/Vocab`. Game text is already localized and is passed through as is.
  - **Drive the game's own handlers** rather than reimplementing flows. **On OXCE never pass a null `Action*`**: many OXCE handlers read it (`_game->isRightClick(action)` and the like), and the next-soldier button crashed on Tab. Build a blank one (`SDL_Event ev = {}; Action action(&ev, 1.0, 1.0, 0, 0);`, with `ev.type`/`ev.button.button` set for a left click when the handler checks the button), as `ComboBox`/`Slider::notifyChange` and `Battle::cycleSoldier` do. (Two older calls still pass 0, `btnEndTurnClick` in `Battle.cpp` and the inventory's `btnOkClick`; neither handler reads it today, but convert them if you touch them.)
  - **Split screens into Tab-stops.** Every new or changed screen must be split sensibly with `GraphBuilder::BeginStop` (one stop per zone: a list, a section, a region group, the buttons), never left as one long arrow list. The user found single-stop screens were leaving a lot of keyboard efficiency on the table (asked 2026-10-05). Arrows never cross a stop; Tab/Shift+Tab cycle them and each remembers its position. Only genuinely small screens (a popup, ~10 controls with no natural sections) stay one stop.

### Code layout

- `src/Access/Speech.{h,cpp}`: `Speech::say(text, interrupt)`, `silence()`, `repeatLast()`, `normalize()`. `normalize` strips `TOK_COLOR_FLIP`, `TOK_NL_SMALL`, newlines and NBSP and collapses whitespace, drops an NBSP between digits (`Unicode::formatNumber`'s thousands separator, "8 000", which screen readers read as two numbers), and turns a lone `>` (the game's "TURN>1" separator) into a colon; runs like `>>` stay. Output is split into chunks of at most 700 bytes. Main thread only.
- `src/Access/Vocab.{h,cpp}`: the `Vocab::Id` enum plus a string table. Keep the two in the same order. `Vocab::format` fills `{0}`, `{1}` placeholders.
- `src/Access/TerrainNames.{h,cpp,inc}`: names for terrain pieces, which the game never names, keyed by MCD set and index (`"CULTIVAT", 9, "apple tree"`). The `.inc` table was labelled by eye from sprite contact sheets made with `scripts/terrain_sheets.py <outdir>` (numbered sprites per set, plus `pieces.csv` with each piece's properties); it covers every vanilla piece that draws something (blank pieces are left out). OXCE replaces 15 sets with patched copies in `bin/standard/xcom1/TERRAIN`; checked 2026-10-06, only LIGHTNIN changed its pieces (41 to 46 now follow OXCE's version), the rest changed properties only. To label OXCE's copies, point the script's `ROOT` at a folder holding those files plus `GEODATA/PALETTES.DAT`. It's the one place mod text lives outside Vocab. Fix a wrong name directly in the `.inc`.
- `src/Access/Graph/`: the graph kernel, copied verbatim from sims2access (deltas: the namespace is `OpenXcom::Graph`, and one C++20 `std::erase_if` is spelled the C++17 way). STL-only, no game headers. Don't edit it for OpenXcom-specific needs; fix upstream and re-copy.
- `tests/graph/`: the kernel conformance suite. Run `tests/graph/build.cmd` (needs C++20, so it builds outside the game; output in `build/graphtests/`).
- `src/Access/Navigator.{h,cpp}`: screen manager plus navigator. Each frame it matches the top `State` against the recipes (poll and diff), keeps a `GraphState` per live `State` so covered screens restore focus, and runs the announce-once differ. Every recipe and layer callback runs guarded: a throw is logged to `openxcom.log` and spoken once per attach ("Accessibility error on newGame, in build: ..."), so a broken screen doesn't just go silent. `handleEvent` is called from `Game::run` before the game sees an event; it swallows claimed key-downs and their key-ups. It stands down while a `TextEdit` is focused, except for the typing echo (`watchEdit`, a differ over the field's text and `TextEdit::getCaretPos`: "Editing X" on focus, then the characters typed or deleted, or the one the caret lands on, "blank" at the end) and Ctrl+L, which reads the whole field. `update` skips frames until the top state has run `init()` (`Game::isStateInitialized`); many states set up widgets there, so reading earlier announces half-built screens. (`handleEvent` doesn't check this, so a key pressed in that first frame can build a recipe early.) Game-side hooks (`Battle::beginImpact`/`endImpact`/`shotOffMap`, `Dogfight::status`, the `WarningMessage` speech) are called by the game directly and aren't guarded, so a throw there reaches the game loop.
- Recipes match first-wins: `sync` takes the first recipe in `Screens::all()` whose `isActive` is true, and `is<T>` is a `dynamic_cast`, so a subclass also matches its base's recipe (OXCE's `SkillMenuState` matches the action menu's). Registry order matters when adding one.
- Keys on a recipe screen that `dispatch` doesn't handle (letters, digits, F-keys, Ctrl+Up/Down, Ctrl+Left/Right on a node that doesn't adjust) go to the game. Alt+anything is never claimed.

### Keys

- Graph screens: arrows move (Left/Right adjust a slider-like control, Shift for bigger steps, Ctrl all the way: `Controls::ADJUST_LIMIT` as the sign), Home/End jump to the ends, Tab/Shift+Tab cycle zones, Enter activates, Backspace is the secondary action, Space reads the tooltip, Ctrl+L re-reads the focus with its context, Escape is the screen's `back` if it has one (otherwise it goes to the game).
- Battle map (Battlescape on top, no popup): arrows move the cursor by compass (Up = north), Page Up/Down change level, Home returns to the selected soldier, Enter = left click on the cursor tile (preview, then move; fires while targeting), Backspace = right click (cancel preview/targeting, else turn or open a door; this also takes Backspace away from the game's end turn), Escape cancels targeting, Tab/Shift+Tab cycle soldiers, Space = soldier status (this swallows OXCE's night-vision hold), Ctrl+L = cursor tile in full with offset and coordinates, Ctrl+E twice = end turn (swallows OXCE's Ctrl+E and Ctrl+Shift+E experience screens). Shift is ignored on these keys, so Shift+arrow etc. act like the plain key; Shift+Tab is our previous soldier, not OXCE's select-without-centring. Escape is claimed only while targeting. Scanner: Period/Comma step through the current category nearest first, Shift+Period/Comma change category (soldiers, enemies, civilians, items, doors, exits: the craft's entrance tiles, where soldiers must stand to escape an abort, plus stage exit tiles), Slash jumps the cursor there. While aiming (after picking a shot or throw in the action menu) the layer says the action and accuracy, jumps the cursor to the nearest enemy the soldier can see (for a 2×2 unit, `unitTile` picks the quarter the shooter has a line of fire to by `TileEngine::canTargetUnit`, then the nearest; Slash does the same), and adds "in view"/"out of view" for units under the cursor (parity: the HUD's enemy buttons show the same), with a reason (`outOfViewReason`, modelled on vanilla's `TileEngine::visible`: too far, too dark, not facing it, then one eye-to-body-centre line naming what it hits if that tile was seen, or smoke; the game tries several lines, so this is a best guess); Enter fires. Blaster Launcher: Enter drops a waypoint ("waypoint 1 of N"), Enter again on the last waypoint presses the HUD's launch button (`BattlescapeGame::launchAction`); Escape/Backspace remove the last waypoint, then cancel the aim. Stance changes of the selected soldier (K) say "kneeling"/"standing". Visible hostiles carry their facing ("facing south", plus "toward you" when the selected soldier is in their 90° view cone, `BattleUnit::checkViewSector`, which is what reaction fire uses) on the cursor tile, in the scanner and when spotted; the sprite shows the same. Tile descriptions end in "dark" when `Tile::getShade() > TileEngine::getMaxDarknessToSeeUnits()` (a mod value; vanilla rule of thumb: our soldiers can't spot a unit there from beyond 9 tiles, aliens ignore light. OXCE makes the dark range per unit and armour, and `outOfViewReason` still hard-codes 9; see the audit). Open-air tiles leave it to the ground tile they describe. Narration (queued): spotted hostiles, any shown unit killed or knocked out, our soldiers bleeding from fatal wounds at the turn's start ("Vasile Anton bleeding, health 10"; actual hits are spoken at impact), and each shot the player didn't order (`Map::getProjectile`): aliens' fire and our reaction fire on the aliens' turn. A shot is spoken when the Map would draw it (`Map.cpp`'s `_projectileInFOV`): at once on our turn or if the shooter is visible ("Sectoid fires at X"); on the aliens' turn otherwise only once the bullet is on a tile we can see, measured from where it came into view ("fire from northeast, above, at X" if aimed at a shown unit, else "shot seen 3 north, 2 east, heading west" from the last selected soldier). A shot that never enters view is silent: the sighted player gets the hidden movement screen and the same gunshot sound. The shooter is `Projectile::getActor()` (added); a hidden shooter's position is never spoken. Auto-shot bursts are spoken once. A shot leaving the map says "missed" (`Battle::shotOffMap`, called from `ProjectileFlyBState`). Shot results (queued) follow each impact, for our shots and any shot whose shooter or target was shown: "Sectoid Soldier hit" (our units add their health), "missed, hit wooden fence" (the terrain piece struck; a unit we can't see counts as a miss), "explosion hits no one"; a unit the hit takes down gets only the killed/unconscious line. `ExplosionBState::init` brackets `TileEngine::hit`/`explode` with `Battle::beginImpact`/`endImpact` (a health and stun snapshot), and `TileEngine::getLastHitUnit`/`getLastHitPart` (added) say what a bullet struck; there's no pain sound in the game, only death screams. Units that aren't ours are named by race, not rank ("Sectoid", not "Sectoid Leader": every rank shares a sprite; the game shows ranks only in panic messages, mind probes and a stunned body in the inventory, which pass the game's text through), plus a per-sighting number (`unitLabel`): given when first named in view, retired with "lost sight of Sectoid 2" when the unit leaves view, never reused, so a returning alien gets a new number. Left Shift alone is swallowed (vanilla's previous-soldier key; vestigial on OXCE, where that binding defaults to none). The game's reserve keys pass through and are spoken by a differ: F1 to F4 (none, snap, aimed, auto) and J (kneel) with the buttons' tooltips, Delete (expend all TUs) says "all time units spent"; Space includes active reserves. Every `WarningMessage::showMessage` is spoken (battlescape and inventory warnings).

### Key hook points (tactical)

- Main loop and global keys: `Engine/Game.cpp` `Game::run`. The SDL event poll is where to filter keys the layer claims, before `_states.back()->handle()`.
- Screen stack: `Game::pushState`/`popState`. A screen recipe's `IsActive` is a `dynamic_cast` on the top state.
- Battlescape input: `BattlescapeState::handle`. It ignores input while the cursor is hidden. Bindings are declared in `Engine/Options.inc.h`, with defaults in `Options.cpp`; the arrow keys belong to `Camera::keyboardPress`.
- Tile cursor: `Map::setSelectorPosition` takes screen pixels; `Map::setSelectorTile` (added) takes map coordinates. `BattlescapeGame::primaryAction(Position)` and `secondaryAction(Position)` are what a click does.
- Path cost: `Pathfinding::calculate`, then sum `getTUCost` along `getPath()` (not `getTotalTUCost`). Hit chance: `BattleUnit::getFiringAccuracy`.
- Newly spotted units: `BattleUnit::addToVisibleUnits` returns true on first sight.
- Events: the `BattleState` subclasses (`UnitWalkBState`, `ProjectileFlyBState`, `ExplosionBState`, `UnitDieBState`, and so on), plus `BattlescapeGame::checkForCasualties` and `endTurn`.
- Warnings: `WarningMessage::showMessage` (spoken). Selection changes: `BattlescapeState::updateSoldierInfo`.
